# AdSense 재심사 대응 설계 (2026-07-06)

## 배경

Google AdSense 심사가 두 가지 사유로 거절됨:

1. **게시자 콘텐츠가 없는 화면에 Google 게재 광고**
2. **가치가 별로 없는 콘텐츠**

2026-06-17에 신뢰 페이지(about/terms/privacy, `1dcb4c25`)를 추가했으나 재차 거절. 코드·라이브 사이트 조사로 아래 원인을 확정했다.

## 확정된 결정

- **범위**: 전면 대응 (광고 게이팅 + 데이터 채우기 + 콘텐츠 보강)
- **콘텐츠 보강 방식**: 데이터 기반 자동 콘텐츠만 (정적 에디토리얼·가이드 없음)
- **플레이어 데이터 전략**: 랭킹 플레이어 사전 갱신 배치 (A안)

## 목표

1. 게시자 콘텐츠가 없는 어떤 화면에도 광고가 게재되지 않음을 코드 수준에서 보장
2. "저가치 콘텐츠" 신호 제거: 홈·이벤트 페이지를 데이터 기반 콘텐츠로 보강
3. 랭킹에 노출되는 플레이어는 항상 데이터가 있는 상태로 유지
4. 위 상태로 배포·검증 후 AdSense 재심사 요청

## 비목표

- 미갱신 플레이어 방문 시 **자동 갱신 플로우 전환(B안)** — 심사 통과에 기여하지 않고, renewal 엔드포인트 보호장치(rate limit·봇 필터) 선행이 필요해 후속 라운드로 분리
- 브롤러별 랭킹(~72만 건) 사전 갱신 — 규모상 제외
- 정적 에디토리얼 콘텐츠(공략·가이드·FAQ) 작성
- 광고 수익 최적화(배치 개수·포맷 튜닝) — 심사 통과가 우선

## 설계

### 1. 광고 체계 전환: 자동 광고 → 수동 유닛 (imstargg-frontend)

자동 광고는 스크립트가 로드된 페이지에 Google이 임의로 광고를 삽입하며, SPA 클라이언트 내비게이션(콘텐츠 페이지 → 빈 페이지)까지 추적해 삽입하므로 코드에서 스크립트 로드만 조건화해서는 빈 화면 광고를 막을 수 없다. 수동 유닛 전환으로 광고 위치를 결정론적으로 통제한다.

- **AdSense 콘솔에서 자동 광고 OFF** (운영자 액션, §5)
- `AdUnit` 컴포넌트 신설 (`src/components/ads/`): 표준 `<ins class="adsbygoogle">` 반응형 유닛(`data-ad-format="auto"`, `data-full-width-responsive="true"`). **슬롯 ID가 비어 있으면 아무것도 렌더링하지 않음** → 콘솔에서 슬롯 생성 전에도 안전하게 배포 가능
- 슬롯 ID는 `src/components/ads/` 내 상수로 관리 (HTML에 노출되는 공개 값이므로 env 불필요)
- **배치 위치** (콘텐츠 아래·사이에만):
  - 홈 (§3 보강 후 데이터 섹션 하단)
  - `/players`, `/clubs` 랭킹 리스트 하단
  - `/brawlers` 메타 표 하단
  - `/brawlers/[id]` 통계 아래
  - `/events` (§3 보강 후), `/events/[id]` 콘텐츠 아래
  - `/players/[tag]`, `/clubs/[tag]` — **데이터가 있는 경우에만** (`PlayerContent`/클럽 상세 내부에 배치; NotFoundView 경로에는 존재하지 않음)
- **광고가 없어야 하는 화면** (유닛 미배치 + 스크립트 미로드):
  - `PlayerNotFoundView` / 클럽 미갱신 뷰, 전역 404 (`app/not-found.tsx`), `error.tsx`, `/players/search`·`/clubs/search`, `/about`·`/terms`·`/privacy`
- **이중 방어**: `GoogleAdsenseScript`를 루트 레이아웃에서 제거하고, `AdUnit`을 배치하는 페이지에서만 로드되도록 구성 (콘솔의 자동 광고 설정이 실수로 복원돼도 빈 화면에는 스크립트 자체가 없음). 클라이언트 내비게이션으로 스크립트가 이미 로드된 세션에서도, 자동 광고가 OFF이므로 유닛 없는 화면에는 광고가 삽입되지 않는다.

### 2. 빈 상태·색인 정리 (imstargg-frontend)

- 미갱신 플레이어/클럽 페이지: **현행 200 + `noindex, nofollow` 유지**. 갱신 버튼이 동작해야 하는 기능성 화면이므로 404로 바꾸지 않는다. 광고가 사라지면 "알림·행동 목적 화면"으로서 정책 위반이 아니다
- 전역 404: Next.js가 자동으로 `noindex`를 삽입함을 라이브로 확인 — 코드 변경 불필요
- 빈 검색 페이지: 이미 `noindex` 상수 적용 — 변경 불필요
- sitemap: 현행 유지 (플레이어/클럽 상세 미포함이 올바름)

### 3. 데이터 기반 콘텐츠 보강 (imstargg-frontend, 필요 시 core-api)

- **홈페이지** (`app/page.tsx`): 검색창 유지, 아래에 RSC 데이터 섹션 3개 추가
  1. 트로피 랭킹 TOP 10 미리보기 (기존 `/v1/ranking/players` 재사용, 글로벌 기본)
  2. 브롤러 메타 TOP 10 — 승률 상위 (기존 브롤러 통계 API 재사용)
  3. 현재 이벤트 로테이션 미리보기 (기존 events API 재사용)
  - 각 섹션에 해당 목록 페이지로 가는 "더 보기" 링크, 상단에 서비스 소개 한 단락(고정 텍스트)
  - 기존 RSC-first 패턴(`apiFetch` + `next.revalidate`) 준수
- **`/events`**: 이벤트 카드에 통계 요약(예: 전투 표본 수, 최고 승률 브롤러 1~3개) 노출. 이벤트 상세가 이미 쓰는 통계 API로 충당 가능한지 우선 확인하고, 목록 단위 일괄 조회가 필요하면 core-api에 요약 엔드포인트 1개 추가 — **이 경우 API 스펙 동기화 룰에 따라 frontend 반영까지 한 세트**
- 페이지 `description` 메타를 실데이터 기반 문구로 정비 (예: 홈 — 추적 중인 플레이어·전투 규모)

### 4. 랭킹 플레이어 사전 갱신 배치 (core-batch)

- 신규 job `playerRankingRenewalJob` (기존 `RankingCollectJobConfig` 패턴 준수):
  1. 최신 플레이어 트로피 랭킹 스냅샷(글로벌 + 국가별)에서 고유 태그 수집 (최대 ~8,000개)
  2. **필터**: players에 레코드가 없거나 renewal 완료가 24시간보다 오래된 태그만 선별
  3. 기존 renewal 파이프라인과 동일한 상태 머신으로 발행: renewal row 생성/재요청 → SQS 발행 → core-worker가 소비 (worker는 무변경)
  4. **스로틀**: 발행 속도 분당 ~100건 (최악 8,000건 = 약 80분). Brawl Stars API 429 발생 시 worker의 기존 실패 처리(FAILED)를 따르되, 배치 재실행으로 보완
- 스케줄: 일 1회, `rankingCollectJob` 이후 실행
- 비용 추정: 첫 실행 최대 ~16,000 BS API 호출, 이후 랭킹 신규 진입자·만료분만(일 수백 건 수준 예상)
- 효과: `/players`·`/clubs` 랭킹의 모든 플레이어 링크가 콘텐츠 있는 페이지로 연결

### 5. 배포·검증·재심사 절차

1. 구현 완료 → `develop` → `main` 배포 (backend: core-api 변경 시 core-api, core-batch / frontend)
2. **라이브 검증 체크리스트**:
   - 미갱신 플레이어 페이지: `ins.adsbygoogle` 0개, 광고 iframe 0개, AdSense 스크립트 미로드
   - 404·빈 검색·법적 페이지: 동일하게 광고 요소 0개
   - 홈: 데이터 섹션 3개 렌더링, 본문 텍스트가 유의미한 분량으로 증가
   - `/players` 랭킹 상위 N명 링크 표본 확인: 전원 데이터 존재
   - 콘텐츠 페이지: AdUnit(`ins` 요소)에 슬롯 ID 반영 확인 — 승인 전에는 광고가 표시되지 않는 것이 정상
3. **운영자 액션** (코드로 불가능한 부분):
   - AdSense 콘솔에서 **자동 광고 OFF**
   - 광고 유닛(슬롯) 생성 후 슬롯 ID 전달 → 상수 반영 배포
   - 위 검증 통과 후 **재심사 요청**

## 테스트 전략

- **frontend** (기존 원칙: MSW 네트워크 경계 모킹, 사용자 관점 쿼리):
  - `AdUnit`: 슬롯 ID 유무에 따른 렌더/미렌더 단위 테스트
  - 홈 데이터 섹션: RSC 렌더 테스트 (랭킹/메타/이벤트 표본)
  - E2E (Playwright): 미갱신 플레이어 페이지에 `ins.adsbygoogle` 및 AdSense 스크립트 부재 단언 — **회귀 방지 핵심**
- **core-batch**: 태그 수집·필터(미존재/24h 초과)·스로틀 로직 단위 테스트, 기존 job 테스트 패턴 준수
- **core-api** (요약 엔드포인트 추가 시): 컨트롤러 테스트 + frontend 타입 동기화

## 가정과 리스크

| 항목 | 내용 | 대응 |
|---|---|---|
| BS API 쿼터 | 일 ~16k 추가 호출 여유 가정 | 스로틀 + 429 시 FAILED → 익일 배치가 자연 재시도 |
| 자동 광고 재활성화 실수 | 콘솔 설정은 코드 밖 | 빈 화면에는 스크립트 자체를 미로드 (이중 방어) |
| 심사 재거절 | 심사 기준 불투명 | 두 사유(빈 화면 광고·저가치)를 모두 해소하는 구성. 재거절 시 피드백 기반 후속 라운드 |
| 랭킹 외 미갱신 페이지 | 직접 URL·검색 유입은 여전히 빈 상태 | 광고 미게재 + noindex로 정책·색인 문제 없음. UX 개선(자동 갱신)은 후속 라운드 |

## 후속 라운드 후보 (이번 범위 아님)

- 자동 갱신 플로우 전환 (renewal rate limit·봇 필터 선행)
- 정적 에디토리얼 콘텐츠 (브롤러 소개, 모드/맵 설명)
- 광고 배치 수익 최적화
