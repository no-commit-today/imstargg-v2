## 변경 사항

### core-api 0.2.0

#### Feedback 도메인 재설계

- `POST /v1/feedback` 요청 본문을 `{category}` → `{rating: 1..5, content}` 로 교체.
- `Feedback` / `FeedbackCreate` 도메인에 `rating` + `submittedAt` 도입, `FeedbackService` 가 `Clock` 을 주입받아 `submittedAt` 을 명시적으로 세팅.
- `FeedbackRepository` 시그니처를 새 도메인에 맞춰 갱신, `FeedbackControllerTest` / `FeedbackServiceTest` 를 `Clock.fixed` 기반 rating 케이스로 교체.

#### 통계 Repository 재구성

- BattleResult / BattleRank / Pair 통계 Repository 가 raw row 대신 도메인 `Statistics` 객체를 반환하도록 재구성.
- `BrawlerResultStatistics.create` 가 `GameSlots` 를 입력으로 받도록 변경.
- 통계 Service / WithCache 위임에 named arguments 적용, Pair 다중 날짜 분모 검증 테스트 추가.
- 불필요해진 도메인 객체 (`SlotsPerGame`, `RawCounts`, `EventTotalSlotSum`, `BrawlerPairRankCounts`) 제거.

#### GameSlot 도메인 객체

- `GameSlot` 값 객체 + `GameSlots` 컬렉션 도입 (missing event 는 default 폴백).
- `GameSlotRepository` 추가 — `BattleEvent` → `GameSlot` 변환.

### core-batch 0.2.0

#### Feedback Digest 재작성

- 24h 다이제스트를 `submittedAt` 범위 조회 + rating 카운트로 교체.
- `FeedbackDigestMessage` 를 rating 분포 기반 (1~5점 카운트 + 평균) 으로 재작성.

#### 통계 잡 평탄화

- 5개 통계 잡 평탄화 — `BrawlerBattleResultStatsJob`, `BrawlerBattleRankStatsJob`, `BrawlerPairBattleResultStatsJob`, `BrawlerPairBattleRankStatsJob`, `BrawlerEnemyBattleResultStatsJob`.
- `BrawlerBattleResultStatsTaskTest` 행위 검증 보강.
- 사용하지 않는 공통 집계 task 제거.

#### 기타

- `BrawlerSyncTask` 의 item 변경 감지 로직을 헬퍼로 추출.

### core-worker 0.1.2

- 직접적인 동작 변경 없음 — `core-enum` (`FeedbackCategory` 제거, `FeedbackRating` 추가) 및 `db-core` (`FeedbackEntity` / 통계 Repository) 라이브러리 변경 흡수.

### frontend 0.2.0

#### Feedback UI 재작성

- `FeedbackForm` 을 5단계 만족도 (이모지 + 라벨) + 의견 입력으로 재작성, `FeedbackDialog` 타이틀/부제 새 카피로 교체.
- `feedback-rating` 라벨/이모지 매핑 신설, `/v1/feedback` 클라이언트 타입을 `{rating, content}` 로 교체.
- 구 `feedback-category` 모듈 삭제.

#### 데이터 테이블 + 게임 액센트 디자인 시스템

- 랭킹·브롤러 탭·이벤트 페이지에 공용 데이터 테이블 + 게임 액센트 디자인 시스템 적용.
- 통계 표 헤더 가독성·정렬·이벤트 디자인 통일.
- 일별 트렌드 차트 툴팁에 스타플레이어 라벨 표시.
- 사용하지 않는 `win-gauge` 컴포넌트 / CSS 제거.

## ⚠️ Breaking Changes

- **`POST /v1/feedback` 요청 본문 교체**: `{category}` → `{rating: 1..5, content}`. core-api ↔ frontend 동시 배포 필수. 구버전 frontend 가 신버전 core-api 에 보내면 400, 반대도 동일.
- **`FeedbackCategory` enum 삭제 (core-enum)**: `FeedbackRating` 으로 교체. core-enum 을 의존하는 모든 모듈 (core-api / core-batch / core-worker / core-admin) 이 동일 버전으로 함께 배포되어야 함.
- **DB `feedback` 테이블 재설계 (V260522)**: `category` 컬럼 제거, `rating(int)` + `submitted_at(timestamp)` 컬럼 도입. forward-only — 구버전 백엔드를 새 스키마에 배포하면 JPA 매핑 실패.
- **core-api 내부 도메인 / Repository 시그니처 변경**: 통계 Repository 들이 raw row 대신 `Statistics` 객체 반환. 외부 API 응답 형식 변경은 아니지만, 모듈 간 바이너리 호환성 깨짐 — 같은 모노레포 내라 한 번에 빌드/배포되므로 실질 영향 없음.

## 마이그레이션 필요 사항

- **DB 마이그레이션** (db-core / Flyway):
  - `V260517__add_feedback_table.sql` — rating 기반 feedback 테이블 신설.
  - `V260518__add_player_club_name_search_index.sql` — player 검색용 인덱스 추가.
  - `V260519__rename_feedback_indexes_to_ix_prefix.sql` — feedback 인덱스 이름 `ix_` prefix 통일.
  - `V260519a__add_player_counts_to_battle_event_mode.sql` — `battle_event_mode` 에 player count 컬럼 추가.
  - `V260520__replace_player_club_search_indexes.sql` — player_club 검색 인덱스 재구성.
  - `V260522__redesign_feedback_to_rating.sql` — feedback 을 `category` → `rating + submitted_at` 구조로 재생성.
- **배포 순서**: db-core 를 공유하는 backend 3개 앱 (core-api / core-batch / core-worker) 은 신버전 동시 배포. frontend 도 core-api 신버전과 함께 배포 (Feedback API 호환성).

## 롤백 시 주의 사항

- **`V260522__redesign_feedback_to_rating.sql` 은 forward-only**. 0.1.x 의 `FeedbackEntity` 는 `category` 컬럼을 매핑하므로, 마이그레이션 후 0.1.x 백엔드를 다시 배포하면 JPA 매핑이 실패한다. 코드 롤백이 필요하면 먼저 `category` 컬럼을 복구하는 보상 마이그레이션을 적용해야 하며, 그 사이 작성된 rating 기반 row 들은 `category` 값으로 자동 복원되지 않는다.
- **`V260517` 이후 인덱스/컬럼 추가 마이그레이션** 은 drop 으로 단순 롤백 가능하지만, 운영 중 dropIndex 는 락 비용 발생 가능 — 트래픽 낮은 시간대 권장.
- **backend 3개 앱 (core-api / core-batch / core-worker) 동시 롤백 원칙** — db-core / core-enum 공유로 한쪽만 롤백 시 enum 미스매치 / Repository 시그니처 충돌 가능.
- **frontend ↔ core-api 는 동시 롤백 권장** — Feedback API 호환성 때문.
