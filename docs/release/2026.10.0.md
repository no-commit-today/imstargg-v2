## 변경 사항

### 브롤스타즈 자원 soft-delete 도입 (b2f88df4)

게임에서 제거된 기어를 `brawler_gear` 에서 행 삭제했는데 브롤스타즈 API 가 계속 응답해, `brawlerSyncJob` 이 실행될 때마다 같은 기어를 "기어 추가"로 감지·알림하던 문제를 해결한다. 행을 지우는 대신 남겨 두고 `deleted_at` 으로 삭제를 표시해, 동기화 배치가 "이미 알고 있는 항목"으로 취급하게 한다.

- `BaseSoftDeleteEntity`(`deletedAt`) 추가 — brawler·gear·brawler_gear·gadget·star_power·hyper_charge·battle_event 엔티티에 적용.
- `@SQLRestriction` 전역 필터는 쓰지 않고 조회 시점에 `...DeletedAtIsNull` 쿼리 메서드로 명시적으로 거른다. 동기화 배치와 관리자는 삭제된 행도 읽어야 하기 때문이다.

### core-batch 0.4.3

- `brawlerSyncJob`: soft-delete 된 브롤러/항목은 API 응답 여부와 무관하게 변경(추가)으로 감지하지 않는다. 삭제된 행까지 읽어 활성/삭제로 나눈 뒤 판단한다.
- `BrawlerChangeDetector`·`BrawlerSyncTask` 테스트 추가.

### core-api 0.5.1

- 브롤러 하위 항목(가젯·스타파워·기어·하이퍼차지) 카탈로그에서 삭제된 항목을 제외한다.
- 브롤러·이벤트 자체는 과거 전투·플레이어 데이터가 ID 로 참조해 이름·이미지를 표시해야 하므로 삭제 여부와 무관하게 그대로 조회한다.
- 응답 형식 변경 없음.

### core-worker 0.2.5

- 공통 모듈(`db-core`) 변경에 따른 버전 동기화. worker 는 soft-delete 대상 엔티티를 쓰지 않아 **동작 변경 없음**.

- core-admin: 기어 연결 갱신을 diff 방식으로 변경 — 해제는 soft-delete, 재연결은 복구 (관리 대상 외 앱).
- `imstargg-tools` 추가 — 에이전트용 PostgreSQL CLI(`bin/db`). 접속정보는 git 제외된 `.secrets/` 의 libpq 서비스 파일로만 읽는다.

## 마이그레이션 필요 사항

**앱 배포 전 운영 DB 에 수동 선적용 필요 (1건). 이 프로젝트는 Flyway 미사용이다.**

### `V261020__add_deleted_at_to_brawlstars_resources.sql`

- 7개 테이블(brawler, brawler_gear, gear, gadget, star_power, hyper_charge, battle_event)에 `deleted_at timestamptz null` 컬럼 추가.
  - 모두 수백 행 이하의 소규모 테이블이고, default 없는 nullable 컬럼 추가는 메타데이터 변경뿐이라 **테이블 재작성·장시간 락이 없다**. 점검 시간대 불필요.
- 게임에서 제거됐지만 API 가 계속 응답하는 브롤러별 기어 8건을 삭제 상태로 `brawler_gear` 에 다시 넣는다 (BROCK·RICO·BO·AMBER·GRIFF 의 RELOAD SPEED, SPIKE STICKY SPIKES, LEON LINGERING SMOKE, AMBER STICKY OIL).
- 멱등: `add column if not exists`, `on conflict do nothing`.
- **배포 순서: DDL 선적용 → core-api / core-batch 배포** (core-worker 는 순서 무관). 신버전 앱은 `deleted_at` 컬럼이 없으면 엔티티 조회가 실패한다. 반대로 구버전 앱은 새 컬럼을 무시하므로 선적용해도 안전하다.
  - 단, DDL 적용 후 core-api 배포 전까지는 구버전 core-api 가 복원된 8건을 활성 기어로 보고 카탈로그에 노출한다. 배포 직후(in-memory 캐시 5분 이내) 사라진다.
- 적용 후 확인: `select count(*) from brawler_gear where deleted_at is not null;` → 8. 기존에 같은 (브롤러, 기어) 행이 남아 있었다면 `on conflict do nothing` 으로 삭제 표시가 안 되므로 그 경우 해당 행에 `deleted_at` 을 직접 채운다.

## 롤백 시 주의 사항

앱 이미지 단순 롤백 가능. 추가한 컬럼은 남겨 둬도 구버전 앱과 호환되므로 DB 를 되돌릴 필요는 없다.

- **core-api**: 롤백하면 삭제 필터가 사라져 복원된 8건의 제거된 기어가 브롤러 카탈로그에 다시 노출된다.
- **core-batch**: 롤백해도 복원된 8건은 행이 존재하므로 "추가" 알림은 다시 생기지 않는다. 다만 이후 새로 soft-delete 하는 항목은 구버전이 활성 항목으로 취급한다.
- **core-worker**: 동작 변경이 없어 롤백 영향 없음.
