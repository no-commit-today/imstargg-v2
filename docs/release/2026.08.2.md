# Release 2026.08.2

- **릴리즈 날짜**: 2026-08-10

PR 1건(#76)만 담긴 소규모 릴리즈다. DB 마이그레이션이 없고 API 응답 스펙도 그대로다.

## 변경 사항

### core-api 0.5.0

#### 경쟁전 이벤트 조회에 `seasonKey` 파라미터 추가 (#76)

- 경쟁전 맵 풀은 시즌마다 달라지는데 `GET /v1/events/solo-rank` 가 현재 시즌으로 고정돼 있어 과거 시즌의 맵 풀을 조회할 수 없었다. 옵션 쿼리 파라미터 `seasonKey` 를 추가했다.
- **생략하면 기존과 동일하게 현재 시즌을 반환**한다. 응답 형식(`ListResponse<BattleEventResponse>`)도 그대로라 기존 클라이언트는 영향받지 않는다.
- 시즌 해석에 `SoloRankSeason.ofKey` 대신 `all(clock)` 매칭을 쓴다. `ofKey` 는 목표 key 에 도달할 때까지 `next()` 를 반복하는 구조라 `"999999999-1"` 같은 값이 들어오면 사실상 무한 루프가 된다. 첫 시즌~현재 시즌으로 범위가 닫힌 `all` 에서 찾으면 형식 오류·미래 시즌·범위 밖 키가 모두 같은 경로로 즉시 `INVALID_REQUEST`(400) 로 거부된다.
- 고정 `Clock` 을 주입한 서비스 테스트 5건 추가 — 기본값(현재 시즌), 과거 시즌 조회, 미래 시즌·형식 오류·과대 시즌 번호 거부.

> 프론트엔드는 이번 릴리즈에서 `seasonKey` 를 아직 사용하지 않는다 (`eventApi.soloRank` 는 파라미터 없이 호출). 옵션 파라미터라 동작에는 문제가 없으며, 과거 시즌 맵 풀 UI 는 후속 작업이다.

### core-batch 0.4.2

#### `BattleEventSyncItemWriter` 테스트 추가 (#76)

- 경쟁전 이벤트 수집에 전용 테스트가 없어 현재 동작을 10개 케이스로 고정했다 — 시즌 키 계산, 청크 안팎의 중복 억제, 경쟁전 외 배틀 무시, 시즌 경계·공백 구간 귀속, 미등록/불일치 이벤트 경고.
- **프로덕션 코드 변경 없음** (테스트만 추가). 버전이 오르는 것은 배포 이미지와 릴리즈 이력을 일치시키기 위함이다.

### frontend 0.7.2

#### 이벤트 목록 카드의 통계 요약 제거 (#76)

- 이벤트 카드에서 "N판 집계 · 승률 1위 브롤러" 줄을 제거했다.
- 이 값을 만들려고 서버 컴포넌트가 **로테이션 이벤트마다 통계 API 를 호출하던 N+1 도 함께 사라졌다**. 이벤트 목록 페이지의 서버 호출이 `2 + N` 건에서 2건으로 줄었다 (N = 로테이션 이벤트 수, 보통 10개 안팎).
- 쓰이지 않게 된 `EventStatsSummary` 타입과 `summaries` prop 전달 체인(`page.tsx` → `EventsListPage` → `RotationSection` → `RotationCard`)도 정리했다.

### core-worker 0.2.4

- 이번 릴리즈에 변경 없음. 2026.08.1 과 동일한 버전이다.

## 검토 결과: 경쟁전 수집 체계 (이번 릴리즈 범위 밖)

PR #76 검토 과정에서 확인한 운영상 한계. 코드 변경은 없고 후속 작업 후보로 남긴다.

- 이벤트 발견이 실제 수집된 배틀 기반이라 **새 시즌 시작 직후 목록이 하루 정도 비어 있다** (`battleEventSyncJob` 은 매일 08:00 KST 실행).
- 통계 배틀 테이블이 10일만 보존되어 **과거 시즌 백필이 불가능**하다 — 현재 데이터는 2026-03 이후 시즌부터 존재한다. `seasonKey` 로 그 이전 시즌을 조회하면 빈 목록이 된다.
- 시즌 도중 맵이 빠지는 경우는 반영되지 않으며, 어드민 정정 수단이 없다.

## ⚠️ Breaking Changes

없음.

- `seasonKey` 는 **옵션 파라미터**이며 생략 시 동작이 이전과 같다. 응답 형식도 변경되지 않았다.
- 이벤트 카드 통계 줄 제거는 사용자에게 보이는 UI 변경이지만 API 계약과 무관하고 프론트 내부 타입 정리에 그치므로 patch 로 나간다.

## 마이그레이션 필요 사항

없음.

- DB 스키마 변경(`.sql` 마이그레이션) 없음, 환경변수 추가 없음, 캐시 키 버전 변경 없음.
- **배포 순서 제약 없음** — core-api / core-batch / frontend 를 임의 순서로 배포해도 된다. core-worker 는 배포 대상이 아니다.

## 롤백 시 주의 사항

특이사항 없음.

- **core-api**: 이미지 단순 롤백 가능. 롤백하면 `seasonKey` 가 인식되지 않아 현재 시즌만 반환하는 이전 동작으로 돌아간다. 프론트엔드가 아직 이 파라미터를 쓰지 않으므로 사용자 영향은 없다.
- **core-batch**: 이미지 단순 롤백 가능 (프로덕션 코드 무변경).
- **frontend**: Vercel 배포 롤백 가능. 롤백하면 이벤트 카드 통계 줄과 함께 통계 API N+1 호출도 되살아난다.
- **core-worker**: 이번 릴리즈에 변경 없음.
