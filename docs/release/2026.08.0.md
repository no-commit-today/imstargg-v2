## 변경 사항

### core-api 0.4.4

#### 플레이어·클럽 갱신이 PENDING 에 영구히 갇히던 레이스 수정 (#70)

- **증상**: 갱신 버튼을 눌러도 완료되지 않고 화면이 계속 "갱신 중…" 으로 남았다. 운영 DB 에 갱신 12건이 PENDING 으로 최장 3개월간 방치돼 있었다.
- **원인**: `RenewalService.doRenew` 가 **① REQUESTED 커밋 → ② SQS 발행 → ③ PENDING 커밋** 순서로 동작했다. worker 는 `status != PENDING` 인 메시지를 버리므로, SQS 전달(수십 ms)이 ③ 커밋보다 빠르면 worker 가 REQUESTED 를 읽고 메시지를 폐기한다. 그 뒤 ③ 이 커밋되어 해당 갱신은 소비자가 사라진 채 영구 PENDING 으로 남는다.
- **수정**: PENDING 커밋을 SQS 발행보다 앞으로 옮겨, worker 가 메시지를 받는 시점에 항상 PENDING 이 보장되도록 했다. player·club 공용 경로(`doRenew`) 한 곳 수정으로 양쪽 모두 해소된다.
- 발행 시점의 상태를 검증하는 회귀 테스트(`SQS 발행 시점에 renewal 은 이미 PENDING 상태다`)를 추가해 순서가 되돌아가면 CI 에서 잡히도록 했다.

### frontend 0.7.0

#### 홈을 검색 진입점으로 단순화 (#68)

- 홈에서 **진행 중 이벤트 로테이션·플레이어 랭킹·브롤러 메타 TOP10·"ImStarGG 소개" 문단**을 제거했다. 홈은 로고와 플레이어 검색만 담당한다.
- 세 섹션이 쓰던 병렬 fetch(랭킹·브롤러 통계·이벤트 로테이션)가 함께 사라져 홈이 완전한 정적 페이지가 됐다 — 백엔드 지연·장애가 검색 진입을 막지 않는다.
- 소개 문단은 같은 내용의 `/about` 페이지가 푸터에서 링크되므로 잃는 정보는 없다.
- 홈 광고 슬롯(`AD_SLOTS.home`)도 제거했다. 값이 빈 문자열이라 `AdUnit` 이 이미 아무것도 렌더링하지 않던 상태라 화면·수익 변화는 없다. `AdUnit` 과 나머지 슬롯은 플레이어·클럽·브롤러·이벤트 페이지에서 계속 쓰인다.

#### 멈춘 갱신을 사용자가 직접 복구할 수 있도록 버튼 조건 수정 (#70)

- 백엔드는 요청 후 10초가 지나면 stale 로 판정해 재요청을 허용(`canRenew=true`)하는데, 기존 UI 는 `progressing=true` 면 버튼을 무조건 잠가 이 복구 경로에 도달할 수 없었다. 위 core-api 레이스로 갇힌 갱신이 영구히 "갱신 중…" 으로 보이던 이유다.
- `progressing` 이어도 `canRenew` 면 버튼을 활성화하고, "갱신이 지연되고 있어요 — 다시 시도해 주세요" 안내를 노출한다. 갱신이 지연돼도 사용자가 스스로 풀 수 있는 경로가 생겼다.

### 기타 (앱 버전 무관)

- `/release` 스킬의 `detect_changed_apps` 기본 base 를 `main` → `origin/main` 으로 변경 (#69). 로컬에 `main` 브랜치가 없는 워크트리에서 변경 감지가 실패하던 문제 해결.

## 롤백 시 주의 사항

- **core-api**: 단순 이미지 롤백 가능. DB·스키마 의존 없음. 롤백 시 갱신이 다시 낮은 확률로 PENDING 에 갇힐 수 있으나 데이터 정합성 문제는 없다.
- **frontend**: Vercel 배포 롤백 가능. 롤백해도 core-api 수정이 남아 있으면 갱신 자체는 정상 동작한다.
