# Release 2026.11.1

- **릴리즈 날짜**: 2026-11-14
- **배포 순서 전문**: PR #83 본문. 아래 "배포 순서 요약"은 그 본문을 줄인 것이다.
- **배포 마감**: core-batch 는 2026-11-15 02:00 KST `partition-manage` 실행 전에 올린다. 그 실행부터 원본 보관이 45일이어야 11-04 원본이 남는다.

## 포함 앱 버전

| 앱 | 버전 | 직전(2026.11.0) | 지금 운영 이미지 |

| core-batch | 1.0.0 | 0.4.5 | 0.4.3 |
| core-worker | 1.0.0 | 0.3.0 | 0.3.0 |
| frontend | 1.0.0 | 0.7.2 | 0.7.2 |

- 네 앱을 1.0.0 으로 맞춘다. 응답 필드와 파라미터를 지우는 API 변경, 되돌릴 수 없는 DDL 이 들어 있다.
- 운영 이미지는 `main` 의 버전보다 뒤에 있다. core-api 0.5.2, core-batch 0.4.4·0.4.5 는 배포된 적이 없어 이번에 함께 나간다(0.5.2·0.4.4 는 동작 변경 없음, 0.4.5 는 원본 보관 45일).
- core-admin 과 admin-frontend 는 버전 관리 대상이 아니다.

### core-api 1.0.0

- 이벤트 모드 응답에서 `color` 를 빼고 `resultType` 이 nullable 이 된다(#81). `resultType` 은 통계 수집 모드 테이블에서 붙인다(#92, 응답 모양은 그대로).
- 조합 API 를 다시 짰다. `pair/rank` 를 지우고 3인 조합과 전체 조합 정렬 API 를 더했다. 조합·카운터 API 에서 `eventId`·`pairBrawlerId` 파라미터를 지웠다(#82).
- 1인 통계 응답의 `tier` 가 표본 부족이면 `null` 이다(#84).
- 옛 통계를 `_backup` 테이블에서 읽는다(#95). 응답은 그대로다.

### core-batch 1.0.0

- 조합 통계 잡을 새 테이블 구조로 바꾸고 3인 조합 잡을 더했다. 쇼다운 조합 순위 잡은 지웠다(#82).
- 집계에서 봇 전투를 뺀다. 일별 1인 잡이 규칙을 감시해 경고를 알린다(봇 전투 제외).
- 운영에서 날마다 실패하던 잡 넷을 고쳤다(#86, #87).
  - 순위형 1인: 20인 솔로 쇼다운(모드 75)의 순위로 실패하던 것. 원본의 팀 구성으로 수집 유형을 정해 지원하는 모드만 집계한다(#92 가 판정 방식을 바꿨다).
  - 카운터·2인: DB 소켓 읽기 제한이 의도와 달리 3초였다. 600초로 둔다.
  - 이벤트 동기화: 실행 인자 `date` 를 받지 못해 한 번도 성공하지 못했다.
  - 잡이 실패하면 Discord 로 알린다.
- 통계 원본 보관이 45일이다(#85).
- 공식 뉴스 수집 잡 `brawlStarsNewsCollectJob` 을 더했다. 공용 Discord 알림 발송기가 전송 실패를 삼키지 않고 던진다(#94).
- 패치 기준 통계 잡 다섯 개를 더했다. 옛 잡은 `_backup` 테이블에 쓴다. 조합 통계의 월 파티션 관리는 뺐다(#95).

### core-worker 1.0.0

- 브롤스타즈 API 클라이언트를 RestClient 로 바꿨다. battlelog 404 계정을 지우지 않고 수집에서만 뺀다(#80).
- 통계 수집 모드를 허용 목록으로 제한하고(#81), 그 목록을 DB 에서 5분마다 다시 읽는다(#92). 기동 때 못 읽으면 기동이 실패한다.
- 동시 battlelog 조회 상한 `app.schedule.stats-battle.concurrency`(기본 3)가 생겼다(#80).

### frontend 1.0.0

- 브롤러 목록에 2인·3인 조합 탭을, 브롤러 상세에 3인 표를 더했다. 이벤트 상세의 선택 브롤러 패널과 쇼다운 조합 순위를 없앴다(#82).
- 카운터 표기를 "이 상대를 만났을 때 내 승률"로 바꿨다(#82).
- 브롤러 티어 산정 방식이 바뀌고, 300판 미만은 "–"(표본 부족)로 보인다. 소개 페이지에 "티어 산정 방식" 절을 더했다(#84).
- 통계를 제공하지 않는 모드의 이벤트 상세에 안내를 보인다(#81).

### 사용자에게 보이는 변화

PR #83 본문의 "릴리즈 노트에 적을 것"에 전부 있다. 큰 것만 적는다.

- 통계를 모으는 모드가 12개로 줄어든다.
- 브롤러 메타 통계(트로피전)에서 봇 전투가 빠져 표본이 줄고 순위가 바뀐다. 전환 이전 기간의 트로피 티어 통계는 비어 보인다.
- 브롤러 티어 등급이 넓게 바뀐다.
- `/events` 의 경쟁전 맵 섹션이 다시 보인다(#87).
- 패치 기준 통계는 이 릴리스에서 화면에 보이지 않는다. 화면은 옛 통계를 그대로 보이고, 전환은 다음 릴리스다. 그때까지 늦게 들어온 전투가 통계에 덜 반영되어 표본 부족이 많이 나온다.

## ⚠️ Breaking Changes

- core-api
  - 이벤트 모드 응답에서 `color` 가 빠지고 `resultType` 이 nullable 이 된다(#81).
  - `GET /v1/statistics/brawler/pair/rank` 를 지운다. 조합·카운터 API 에서 `eventId`·`pairBrawlerId` 파라미터를 지운다(#82).
  - `GET /v1/statistics/brawler/result` 응답의 `tier` 가 `null` 일 수 있다(#84).
  - 프론트는 같은 릴리스에 반영돼 있다.
- core-admin: 모드 유형·인원·색 편집 API 를 지운다(#81). 모드 목록 응답의 `resultType` 이 `statsType` 으로 바뀐다(#92). admin-frontend 도 함께 반영했다.
- core-batch: Discord 전송이 실패하면 알림만 보내는 잡이 실패한다. 배틀 이벤트 동기화는 저장 전에 알리므로 Discord 장애 동안 저장도 멈춘다(#94).

## 마이그레이션 필요 사항

모두 운영 DB 에 직접 적용한다(`psql -v ON_ERROR_STOP=1 -f`). 앱은 DDL 을 적용하지 않는다.

| 파일 | 언제 | 비고 |
|---|---|---|
| `V261102a`, `V261102b` | 새 이미지 전 | 구 앱과 호환된다(#80) |
| `V261113__create_stats_event_mode` | 새 이미지 전 | 없으면 새 core-worker 가 기동하지 못한다. 첫 적용 뒤 다시 돌리지 않는다(#92) |
| `V261113a`, `V261113b` | 새 이미지 전 | 공식 글·패치일 테이블. 패치일 초기값 2026-11-03, 2026-11-11(#94) |
| `V261104a__combo_stats_redesign` | 새 이미지 전 | 파일 전체. 두 번째 트랜잭션까지 커밋된 것을 확인한다(#82) |
| `V261114a__rename_stats_to_backup_and_create_patch_stats` | `V261104a` 가 끝난 뒤, 새 이미지 직전 | 이 뒤로 `V261104a` 를 다시 적용하지 않는다(#95) |
| `V261103__drop_battle_event_mode_stats_columns` | 새 이미지를 확인한 뒤 | 구 앱이 지울 컬럼을 읽는다(#81) |
| `V261104b__drop_combo_stats_legacy` | 며칠 뒤 | 이 뒤로 조합 재구성은 되돌릴 수 없다(#82) |

- `partition-manage.sql` 은 적용하지 않아도 된다. `main` 과 달라진 것은 조합 통계의 월 파티션 함수뿐이고, 이 릴리스의 core-batch 는 그 함수를 부르지 않는다(#95).
- 이 순서를 `main` 의 `schema.sql` 로 만든 로컬 PostgreSQL 18.3 에서 적용해 봤다(2026-11-14). 일곱 파일이 순서대로 오류 없이 적용됐다. `V261114a` 뒤에 `V261104a` 를 다시 적용하면 오류로 멈추고 바뀌는 것이 없었다. 운영 DB 에서는 적용해 보지 않았다.
- 백엔드 이미지가 Java 25 다(#80).
- core-batch 의 DB 소켓 읽기 제한이 600초다(#86).
- 원본 보관이 45일이 되어 원본 총량이 약 30GB 에서 약 135GB 로 는다(#85 의 추정).
- Redis 캐시 키 버전이 바뀐다(#82, #84): `v4:brawlerResultStats`, `v3:brawlerPairResultStats`, `v3:brawlerEnemyResultStats`, 새 키 `v1:brawlerTrioResultStats`·`v1:pairResultRanking`·`v1:trioResultRanking`, 지우는 키 `v1:brawlerPairRankStats`.
- CronJob
  - 이 릴리스의 배포 값에 든 것: `trio-battle-result-stats` 추가, `pair-battle-rank-stats` 삭제(#82).
  - 앱 배포 뒤에 따로 더할 것: `brawlstars-news-collect`(#94), 패치 통계 다섯 개(#95). 배포보다 먼저 더하면 옛 이미지가 모르는 잡 이름으로 뜬다.
- 로컬·개발 DB 에도 `V261113` 을 적용해야 한다. 테이블이 없으면 core-worker 가 기동하지 않는다.

## 배포 순서 요약

1. `main` 에 머지한다. 배포 값이 바로 적용된다.
2. 새 이미지 전의 DDL 을 위 표의 순서로 적용한다. `V261104a` 부터 앱 배포가 끝날 때까지는 통계 요청이 캐시에 없으면 500 이므로 이어서 한다.
3. core-api, core-batch, core-worker 를 배포하고 프론트를 다시 빌드한다.
4. 새 이미지를 확인하고 `V261103` 을 적용한다. core-admin 과 admin-frontend 를 이 릴리스로 다시 띄운다.
5. 배포 뒤 작업: 하키·아레나 맵 등록, 오삭제 복구, 3인 잡 수동 실행, 봇 전투 제외 전환(1인 재집계, 트로피 티어 행 백업 후 삭제).
6. 새 CronJob 여섯 개를 배포 값에 더한다.

`V261114a` 를 적용한 뒤에는 옛 통계 테이블의 이름이 `{이름}_backup` 이다. 5번의 SQL 은 그 이름을 쓴다.

## 롤백 시 주의 사항

- **core-batch 를 0.4.5 미만으로 되돌리지 않는다.** 지금 운영 이미지(0.4.3)는 원본을 10일만 보관해, 되돌리면 다음 02:00 실행에서 실행일 − 10일보다 이른 원본이 한꺼번에 지워진다(#85).
- 직전 이미지는 이 릴리스의 DDL 이전 스키마를 기대한다. DDL 뒤에는 이미지 태그만 되돌릴 수 없다.
  1. `V261114a` 머리말의 되돌리는 SQL 을 적용한다(새 CronJob 을 먼저 뺀다).
  2. `V261103` 뒤라면 지운 컬럼을 다시 만들고 백업에서 복원한다.
  3. `V261104a` 머리말의 롤백 절차를 따른다. `V261104b` 뒤에는 할 수 없다.
  4. 구 이미지를 배포한다.
- 기능 하나만 되돌릴 때는 그 변경을 되돌린 이미지를 새로 빌드해 배포한다(봇 전투 제외, 티어 점수 재설계).
- `stats_event_mode`, 공식 글·패치일 테이블은 남겨 둬도 구 앱에 영향이 없다.
