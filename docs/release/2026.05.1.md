## 마이그레이션 필요 사항

- **DB**: `V260505__drop_stats_rank_star_player.sql` — `stats_rank_battle.star_player_brawlstars_tag` 컬럼 drop. core-api / core-batch / core-worker 가 같은 스키마를 공유하므로 모두 새 버전으로 동시 배포해야 한다.

## 롤백 시 주의 사항

- **`stats_rank_battle.star_player_brawlstars_tag` drop 은 단순 롤백 불가 (forward-only)**. 0.1.0 의 `BaseStatsBattleEntity` / `StatsRankBattleEntity` 는 이 컬럼을 매핑하므로, 컬럼이 drop 된 DB 에 0.1.0 백엔드를 다시 배포하면 JPA select/insert 가 실패한다. 코드 롤백이 필요하면 먼저 컬럼을 복구하는 보상 마이그레이션을 적용한 뒤 진행할 것 — 이때 drop 사이에 쌓인 row 의 값은 NULL 로만 채울 수 있고, 원본 데이터(이전 star player 태그)는 복원되지 않는다.
- 위 사유로 backend 3개 앱(core-api / core-batch / core-worker) 은 **동시에** 신버전 배포해야 하며, 부분 롤백도 동일 원칙을 따른다.
- `BrawlerDetailResponse` → `BrawlerWithItemsResponse` rename 은 JSON 필드(`brawler` / `items`) 가 동일해 frontend ↔ core-api 어느 한쪽만 롤백해도 응답은 호환된다.
