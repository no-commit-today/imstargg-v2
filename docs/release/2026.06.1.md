## 변경 사항

### core-api 0.4.1

#### 결과형 통계 item 전투수 버그 수정

- 2026-05-19 픽률 분모 정정 때 item 단위 `totalBattleCount` 에 전역 게임 수가 복사되어 **모든 브롤러의 전투수가 동일하게 표시되던 버그** 수정.
- result/pair/enemy item 필드를 `battleCount` 로 rename — 브롤러(조합)별 전투 수로 복원 (wrapper 의 `totalBattleCount` 는 전체 표본 유지).
- 응답 DTO 에 구버전 프론트 호환용 `totalBattleCount` getter(= `battleCount`) **임시 유지** — 양쪽 배포 완료 후 제거 예정.
- statistics Redis 캐시 키 **v1 → v2 bump** (result/pair/enemy).

#### 공통 리팩토링 흡수 (#52)

- 시간 필드 `OffsetDateTime` → `Instant` 전환, 부모-자식 엔티티 ID 참조 → `@ManyToOne(LAZY)` 전환 (db-core).

### core-batch 0.3.0

#### 배치 잡 재설계 (#52)

- **brawler sync 변경 모델 통합 재설계** — domain 하위 패키지 재구성.
- **랭킹 수집 잡 3개(player/club/brawler)를 `rankingCollectJob` 으로 통합**.
- **브롤스타즈 API 스펙(swagger) 변경 추적 잡 추가** — `brawlstars_api_spec` 테이블 신규.
- CronJob jar 경로 수정·잡 등록·스케줄 KST→UTC 보정 (deploy values).

### core-worker 0.2.2

- db-core 공통 리팩토링 흡수 (`OffsetDateTime`→`Instant`, `@ManyToOne` 전환) — **직접적인 워커 로직 변경 없음**.

### frontend 0.4.1

- 결과형 통계 타입/매퍼/테이블 컴포넌트를 `battleCount` 필드로 동기화 (core-api 버그 수정 연동).

## ⚠️ Breaking Changes

- **core-api 결과형 통계 item 응답 필드 rename** (`totalBattleCount` → `battleCount`) — 단, 구버전 호환 getter 가 임시 유지되어 **이번 릴리즈에서는 비파괴**. frontend 0.4.1 배포 후 다음 릴리즈에서 호환 getter 제거 예정.

## 마이그레이션 필요 사항

- **DB 마이그레이션** (db-core / Flyway): `V260606__add_brawlstars_api_spec_table.sql` — `brawlstars_api_spec` 테이블 신규 추가 (additive, 데이터 손실 없음).
- **Redis 캐시 키 버전 업**: statistics result/pair/enemy 키 v1 → v2. 배포 직후 해당 통계는 cold start (재집계 조회). v1 키는 TTL 만료로 자연 소멸.
- **core-batch CronJob 재등록**: 랭킹 수집 잡 3개 → `rankingCollectJob` 통합 + API 스펙 추적 잡 추가 — deploy values 의 잡 목록·스케줄(UTC) 변경 반영 필요.
- **배포 순서**: core-api(호환 getter 포함)가 frontend 보다 **선행 또는 동시** 배포돼야 한다.

## 롤백 시 주의 사항

- **core-api**: 단순 롤백 가능 — 구버전은 v1 캐시 키를 사용하므로 v2 키와 충돌 없음.
- **core-batch**: 롤백 시 deploy values(CronJob 잡 목록·스케줄)도 함께 롤백해야 구버전 잡 3개가 다시 동작한다. `brawlstars_api_spec` 테이블은 additive 라 그대로 둬도 무방.
- **frontend**: core-api 의 호환 getter 가 유지되는 동안 단독 롤백 가능.
