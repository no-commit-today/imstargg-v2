1. 개요

이슈 #49는 imstargg-frontend의 여러 UI/UX 개선 항목을 묶은 이슈다. 본 설계는 그중 구체적 UI 수정(항목 1~8)과 갱신(renewal) 로직 hook 추상화(항목 11)를 단일 작업 단위로 다룬다. 전반 코드 리팩터링(항목 9)과 아키텍처 검토(항목 10)는 범위가 넓고 탐색적이므로 별도 검토 사이클로 분리한다.

모든 시각 변경은 로컬에서 실행 중인 core-api(8080)에 연결한 dev 서버를 띄워 playwright로 데스크탑(1280px)·모바일(390px) 양쪽을 직접 검증한 현황을 근거로 한다.

2. 범위

포함

  • 항목 1, 2, 3a, 3c, 4, 5, 6, 7, 8 — 구체적 UI 수정
  • 항목 11 — 갱신 hook 추상화

제외 / 종료

  • 종료 항목 3b(브롤러 역할 아이콘만 남기기) — 검증 결과 브롤러 메타 표는 이미 역할 아이콘만 표시하고 역할명 텍스트가 없음. 추가 변경 불필요.
  • 분리 항목 9(전반 리팩터링), 10(아키텍처 검토) — 별도 사이클.

5. 영역별 상세 설계

A. 헤더 / 네비게이션 (항목 1, 6)

대상: src/components/layout/TopNav.tsx, app/styles/app.css

  • 피드백 버튼: 아이콘 + "피드백" 텍스트를 가로(row) 배치로(아이콘 왼쪽, 텍스트 오른쪽). 세로로 보이게 만드는 현재 스타일 원인을 구현 시 특정해 수정.
  • 모바일 드로어: 플레이어 검색창 제거(항목 1), "피드백" 항목 제거(항목 6). 모바일 헤더의 피드백 아이콘 버튼은 유지.
  • 수용 기준: 데스크탑 피드백 버튼이 한 줄 가로 배치 · 모바일 드로어에 검색창과 피드백 항목이 없음 · 모바일 헤더 피드백 아이콘은 동작 유지

B. 이벤트 페이지 (항목 2, 3c, 4)

대상: app/events/_components/EventSearch.tsx, RotationCard.tsx, SoloRankCard.tsx, modeStyles.ts, app/styles/app.css

  • 맵 검색창: PC에서 max-width ~360px + 좌측 정렬. 모바일은 전체 폭 유지.
  • 카드 축소: 헤더/바디/푸터 패딩·폰트 축소로 높이 컴팩트화. PC 그리드 열 증가 검토(현 xl:grid-cols-3 → 4열 후보). 모바일은 카드 높이 축소로 한 화면에 더 많이.
  • LIVE 뱃지 제거: .event-card-live 및 렌더링 제거.
  • 모드 색상(단색화): modeStyles.ts의 그라디언트를 단색 배경으로 교체. 배경 명도(luminance)에 따라 텍스트/아이콘 전경색을 밝음/어두움으로 자동 대비.

  • 수용 기준: PC 맵 검색창이 과도하게 넓지 않음 · 카드가 더 컴팩트해 한 화면에 더 많이 노출 · LIVE 뱃지 없음 · 모드 헤더가 지정 단색으로 표시되고 텍스트 가독성 확보

C. 플레이어 상세 (항목 3a, 8)

대상: app/players/[tag]/_components/PlayerHero.tsx, .../battle/BattleRowHeader.tsx, app/styles/battle.css, src/components/ui/tooltip.tsx, src/lib/relativeTime.ts

  • 히어로 카드(모바일): 아바타 80→64px 축소, 이름 잘림 완화(공간 확보), "클럽:" 2줄 깨짐 수정(white-space:nowrap/라벨 정리), 최근 업데이트·갱신 버튼 배치 정돈.
  • 배틀 행(모바일): 우측 결과 뱃지 화면 밖 잘림 수정 — 그리드 컬럼 폭 재배분으로 결과 뱃지가 항상 보이도록. 브롤러/아이템(기어 등) 이미지 크기 적정화.
  • 배틀 시간: PC는 상대시간에 Radix 툴팁(hover) → 실제시간. 모바일은 상대시간을 다시 노출하고 탭 시 동일 툴팁. relativeTime.ts에 절대시간 포맷 함수 추가.
  • 수용 기준: 모바일에서 "클럽:" 등 라벨이 2줄로 깨지지 않음 · 배틀 결과 뱃지가 화면 안에 완전히 보임 · PC hover / 모바일 탭으로 실제시간 확인 가능

D. 랭킹 나라 선택 (항목 7)

대상: src/components/ranking/CountryFlagPills.tsx → Select 기반, src/components/ui/select.tsx 재사용

  • 국기 pill 버튼 그룹 → shadcn Select(국기 + 국가명). 기존 URL 쿼리(?country=…) 연동·활성 상태 유지.
  • 수용 기준: 셀렉트로 국가 변경 시 기존과 동일하게 랭킹 갱신 · URL 동기화 유지 · 모바일에서 공간 절약

E. 검색 기록 트로피 (항목 5)

대상: src/components/shared/SearchHistoryDropdown.tsx (필요 시 src/components/primitives/Trophy.tsx 재사용)

  • 최근 검색 항목의 이모지 🏆 → /assets/icon_trophy.png 이미지로 교체(<Image unoptimized> 패턴 또는 기존 Trophy 컴포넌트 재사용).
  • 수용 기준: 최근 검색의 트로피 아이콘이 icon_trophy.png로 표시되고 숫자 정렬·정합 유지

F. 갱신 hook 추상화 (항목 11)

대상: src/hooks/usePlayerRenewal.ts, src/hooks/useClubRenewal.ts → 공통 src/hooks/useRenewal.ts

  • useRenewal(kind: 'player' | 'club', tag) 제네릭 훅으로 통합. 폴링(progressing 1초)·전환 시 invalidate·trigger mutation 로직을 단일화.
  • 기존 usePlayerRenewal/useClubRenewal는 얇은 래퍼로 남겨 호출부 시그니처 호환 유지 → 동작 보존.
  • 수용 기준: 중복 로직 제거 · 플레이어/클럽 갱신 버튼·상태 표시가 기존과 동일하게 동작(회귀 없음) · typecheck 통과

6. 검증 & 테스트 전략

  • 각 영역 변경 후 실행 중인 앱을 playwright로 데스크탑(1280)·모바일(390) 재확인 — 특히 잘림/2줄 깨짐 해소를 스크린샷으로 확인.
  • pnpm typecheck + pnpm lint 통과.
  • useRenewal은 동작 보존 변경 — 기존 갱신 흐름 회귀 확인.
  • 변경이 스타일/레이아웃 위주라 신규 단위 테스트 대상은 적음. 순수 함수(relativeTime.ts 절대시간 포맷) 추가 시 단위 테스트 보강.
  • 테스트 원칙 준수: 네트워크 경계만 모킹(MSW), 사용자 관점 쿼리.

7. 작업 순서(제안)

  1. F — 갱신 hook 추상화 (독립적, 로직)
  2. E — 검색기록 트로피 아이콘
  3. A — 헤더/네비(피드백 버튼, 모바일 드로어)
  4. D — 랭킹 나라 선택 셀렉트
  5. B — 이벤트 페이지(검색창·카드·LIVE·색상)
  6. C — 플레이어 상세(히어로·배틀·시간)

각 단계마다 커밋 + 시각 검증. 마지막에 전체 데스크탑/모바일 회귀 확인.

8. 범위 외 / 후속

  • 항목 9(전반 코드/로직 리팩터링), 10(아키텍처 검토): 별도 검토 사이클. 참고로 현황 탐색에서 발견된 후보 — 컴포넌트가 src/api를 직접 호출하는 3곳(PlayerSearchInput, RenewalCard, FeedbackForm), 큰 컴포넌트(SearchableInput 342줄 등).
